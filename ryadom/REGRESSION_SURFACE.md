# Изменённые существующие пути

Изменения ядра включаются Cargo-функцией `ryadom`, зависимостями `direct-only`/`ryadom-turn`
и Flutter-параметром `RYADOM=true`. Без флагов остаётся исходный путь.
Семейный вариант отдельно включает `ryadom-bundled-turn`; общий пароль
обфусцирован в EXE и извлекаем получателем. В исходниках и веб-сборке его нет.
В protobuf добавлено поле 100 и поля 3/4 сообщения Hash с версией подсказки
о наличии пароля, без изменения прежних номеров. Совместимость
с обычными клиентами RustDesk не заявляется.

Новое состояние проб и их отмены находится в собственном `codec_auto.dart`:
записываемый параметр Auto отделён от измеренного предпочтения ядра, ручной выбор
отменяет пробы, закрытие восстанавливает исходное предпочтение незавершённой пробы.
Качество, частота кадров и разрешение не меняются для получения более высокого FPS.
Собственный браузерный движок использует аналогичные пробы WebCodecs.
Новые модули указки, авторизации и подсказок не переписывают legacy-пути.

Новая логика расположена в отдельных файлах. Версия submodule не обновлялась;
патч относится к исходному коммиту. Автомобильные проекты вне `ryadom` не менялись.
Проверка минимальности diff включает перечисленные существующие файлы и патч
закреплённого submodule. Форматирование старого кода и посторонние
предупреждения не исправлялись. Девять тестов собственного Windows-ядра и пять
сетевых тестов прошли. Проверки новых функций с двумя физическими ПК и установленной службой
ещё необходимы. Новая регистрация коротких ID находится в отдельном модуле;
сохранённые пароли и адресная книга по-прежнему используют криптографический ID.

## Отказ получения ID от 14.11.2026

Подтверждён HTTP 403 в журнале второго ПК. Добавлен отдельный `registration.rs`:
читаемый статус регистрации без передачи сырого текста ошибок с возможными
токенами. `signaling.rs` и `short_code.rs` обновляют его в своих существующих
циклах повторов; активный номер не возвращается при потере регистрации устройства.
`src/ipc.rs` получил один read-only getter, C ABI — два read-only действия
`registration-state` и `signal-url`. Сгенерированные FFI-сигнатуры не менялись.
На домашней странице свой таймер читает статус в отдельном Dart isolate и
отменяется при dispose; этот новый жизненный цикл нужен, чтобы не блокировать
интерфейс IPC-запросом и объяснять реальный отказ вместо вечного «Получаем ID».
Остальные страницы и legacy-путь без `ryadom` не менялись.

Адрес службы вынесен в один публичный `signaling.json`; Rust, Dart lookup и
TypeScript используют его, чтобы короткий номер и криптографическая личность
регистрировались в одном реестре. Новая служба Workers — отдельный модуль,
парольная авторизация, DTLS и транспорт сеанса не меняются.
Проверки: отказ 403 в Flutter, безопасное сообщение ошибки в Rust, локальная
и опубликованная регистрация/маршрутизация Workers. Работу без VPN в сети
второго ПК эти проверки не подтвердили.

## Подготовка alwaysdata Free, 14.11.2026

Изменён собственный серверный runtime-путь
`signaling-service/peer-server/server.mjs`: адрес прослушивания теперь берётся
из `IP`/`HOST` площадки, с прежним `0.0.0.0` по умолчанию. Это требуется по
документации alwaysdata; порт уже поддерживал `PORT`. Добавлены только GET-маршруты
`/health`, `/check`, `/check.js` для физической проверки соединения; ответы имеют
`no-store`, чтобы кэш не создавал ложного впечатления доступности. В Dockerfile
добавлено копирование этих публичных файлов; существующий проверочный сценарий
дополнен проверкой health и страницы. Новых зависимостей и тестового фреймворка нет.

Существующий интеграционный тест повторно прошёл с `IP=127.0.0.1`, `PORT=9001`.
README дополнен условиями и порядком размещения, JSON-проверки отличают
доступность сайта/кабинета от ещё не проверенного серверного WebSocket.
Архив содержит 11 исходных файлов и уведомлений о лицензиях, без ключей
развёртывания. Владелец отдельно разрешил SSH-ключ и размещение на Free;
закрытый ключ находится только в игнорируемой `.tools/alwaysdata`.

После успешной повторной проверки WebSocket без VPN на втором ноутбуке изменён
один runtime-конфиг приложения — `signaling.json`: адрес и имя провайдера.
Существующие Rust, Dart и TypeScript читают его без изменений кода. Это необходимо
для получения ID и поиска по номеру через доступный сервер. Пароли, личность
устройства, интерфейс, WebRTC и ExpressTURN сохраняют существующие пути.
README, сетевой документ, инструкция двух ПК и verification.json обновлены
под фактический результат; предыдущие EXE сохранены в истории.

`ryadom/package-development.ps1` получил узкое исключение Git safe.directory
только для собственного `libs/hbb_common` и проверку ошибки перечисления.
Это необходимо: архивирование в ограниченной среде иначе молча пропускало
исходники submodule из-за другого Windows-владельца. Глобальные настройки Git
не менялись; пути приложения и содержимое исполняемых файлов не затронуты.

## Курсоры и повторный доступ, 14.11.2026

Этот раздел описывает предыдущую сборку. Новое поведение разового доступа
при сетевом обрыве описано ниже: оно заменяет прежнее повторное подтверждение.

Проверка минимальности выполнена относительно исходников предыдущей семейной
сборки из `dist/history/2026-11-14-before-session-fixes`:

- `flutter/lib/ryadom/remote_cursor.dart`: собственный виджет скрывает курсор
  через 5 секунд без изменения абсолютных координат. Таймер отменяется при dispose;

- `flutter/web/js/src/media.ts`: такой же срок показа и отмена таймера при закрытии.
  Декодеры, транспорт и запись не менялись.
- `src/whiteboard/windows.rs`: только Ryadom исключает окно указки из захвата
  через Windows display affinity и обрабатывает уже существующий Clear.
  Это убирает обратное изображение собственной указки и след старого сеанса.
  На Windows до 10 2004 указка не запускается, чтобы старый WDA_MONITOR не
  закрыл изображение чёрным прямоугольником. Фактический DXGI/GDI результат
  и переключение мониторов требуют повторной проверки на двух ПК.

  эвристика блокирования мыши по координатам удалённого курсора. Проверка права
  управления, режим просмотра и разрешения по-прежнему исполняются на хосте.
  Остальные сборки сохраняют прежнюю эвристику.
- `src/client.rs`: локальный connection token с session ID доступен и после
  ручного подтверждения без пароля. Он не отменяет авторизацию новых каналов.
  `src/server/ryadom_floor.rs`: подтверждённые каналы мониторов с тем же ненулевым
  SessionKey разделяют управление; передача другому участнику отзывает его у всех.
  При уходе основного канала ввод освобождается до передачи оставшемуся монитору.
  Файловые и терминальные права сохраняют ограничения основного сеанса.
- `src/server/connection.rs`: разовый Click-доступ завершается при обнаруженном
  WebRTC Disconnected; новая попытка проходит штатную ручную авторизацию.
  Постоянный пароль и прочие способы авторизации не затронуты. Обычный входящий
  сеанс отправляет отдельный switch-request вместо неразрешённого SwitchBack.
- `src/ryadom/native_bridge.rs`, `flutter/lib/models/model.dart`: новый запрос
  смены сторон открывает существующее подтверждение показа своего экрана.
  Разрешение исходного SwitchBack и одноразовый UUID не ослаблены.
- `flutter/lib/desktop/pages/server_page.dart`: кнопка смены сторон видна для
  обычного принятого сеанса рабочего стола. `models/server_model.dart` только
  для Ryadom отменяет прежнее сворачивание окна через 3 секунды, чтобы были видны
  запросы подтверждения и кнопки принятого сеанса. Новая неподтверждённая попытка
  заменяет устаревшую строку с тем же ID, вместо сохранения старого состояния
  «принято»/«отключено» при перезапуске серверного процесса.
- `.github/workflows/flutter-build.yml`: добавлен запуск Ryadom-тестов в
  существующий Windows x64 job. Зависимости и bridge codegen не менялись.

Добавлены два узких теста: срок показа курсора (включая масштаб/повторное движение/
dispose) и общее управление мониторами с отзывом при передаче другому участнику.

## Проверка одностороннего TURN

Изменены только три существующих пути выполнения:

- `src/ryadom/network_helper.rs`: read-only snapshot количества эффективных
  TURN-серверов, признака встроенной конфигурации и процесса принимающего ядра.
  Снимок не содержит IP, адресов серверов, ключей, паролей или SDP.
- `src/ipc.rs`: один новый Config read-key внутри существующей ветки
  `feature = ryadom`. Остальные запросы и ветка без этой функции не меняются.
- `src/ryadom/mod.rs`: отдельная команда `--ryadom-network-status` запрашивает
  состояние backend через существующий IPC, проверяет поддержку и выводит только
  разрешённые поля. Подстановки состояния frontend при ошибке нет. Ошибка этой
  команды явно выводится в stderr и завершает внутренний EXE с кодом 1, поскольку
  общий GUI entry point иначе завершает ошибки CLI без видимого результата.

Эта диагностика необходима, потому что новый Portable может обращаться к старой
установленной службе. Отсутствие TURN в DLL окна само по себе недостаточно.
Обычная авторизация, ICE, ввод, файлы, установщик и параметры сети не изменены.
Нормальный запуск идёт прежним путём. Существующая общая инициализация идентичности
перед CLI остаётся прежней; сама новая команда не записывает конфигурацию.

Локально проверено: настоящий ExpressTURN с одной стороны, вторая сторона без
TURN credentials; selected pair `relay/srflx`, 131 072 проверенных application
bytes суммарно. Native suite: 18 passed, 2 ignored. Первый запуск в изолированном
Windows-профиле не выполнил DPAPI-операцию; тот же тест без изменения исходников
прошёл в обычном профиле владельца. Оба лога сохранены. Служба владельца и его
установленная DLL не менялись. Проверка между физическими ПК отложена владельцем;
её результат этим отчётом не объявляется успешным.

## Setup, Portable и тема интерфейса

- `libs/portable/Cargo.toml`: отдельный build feature для Setup без новых зависимостей.
- `libs/portable/src/main.rs`: только Ryadom выбирает режим из сборки, не из имени;
  установка использует существующий параметр каталога распаковки для новой временной
  папки. Обычный Portable сохраняет свой кеш. Stock-ветви сохраняют прежнее поведение.
  Свежая папка Ryadom копирует RuntimeBroker без завершения работающего процесса.
- `ryadom/build-windows.ps1`, `ryadom/signing/artifacts.ps1`: отдельно собирают
  оба внешних EXE из одного payload, чтобы Setup не был копией Portable.
- `flutter/lib/ryadom/home_content.dart`: согласованные цвета двух тем, отдельные
  общие настройки и «P2P / TURN», явная кнопка включения ранее остановленного приёма.
- `flutter/lib/ryadom/home_page.dart`: передача callbacks и штатный `start_service(true)`
  только после нажатия владельца; сохранённый запрет приёма автоматически не сбрасывается.
- `flutter/lib/desktop/pages/desktop_home_page.dart`: ссылка на прежний полный экран
  настроек в ветке Ryadom, с прежними ограничениями доступа.
- `flutter/test/ryadom_home_layout_test.dart`: регрессия тёмного контраста, действий
  кнопок и компактной компоновки. Новая инфраструктура тестирования не вводилась.

Проверки: по 8 тестов упаковщика с обычным и установочным режимом; 4 widget-теста,
включая увеличенный текст и контраст не ниже 4.5:1 у проверяемых надписей.
Ядро прямого соединения, авторизация, файлы, ввод и жизненный цикл службы не менялись.
Семейный и публичный варианты ядра проверяются отдельно по встроенному TURN.

## Установка после выключения приёма

- `src/platform/windows/ryadom_autostart.rs`: только Setup при остановленном приёме
  или outgoing-only сохраняет выбор автозапуска без требования отсутствующей службы
  и ярлыка. Обычный режим и ручное переключение остаются прежними.
- `src/platform/windows/ryadom_install.rs`: защищённый ключ раскрывается перед
  повторной защитой для компьютера. ID, пароль и остальные настройки не меняются;
  существующий тест использует защищённый пользовательский ключ.
- `src/platform/windows/installer_handoff.rs`: Ryadom-only расшифровка пяти кодов
  ошибок; обычный elevated handoff и поведение без этой функции не менялись.

После исправлений: 19 native-тестов прошли, 2 внешних испытания пропущены.
Отдельно проверяется установка на физическом ПК; unit-тесты не подменяют её.

## Принудительный TURN в Windows

- `src/client.rs`: только ветка `ryadom` передаёт явный `policy_relay` в отдельный
  путь подключения. Транспортное требование WebSocket не принуждает TURN.
- `src/ryadom/mod.rs`: принудительное подключение обходит подготовленный P2P,
  проверяет выбранный TURN и сохраняет прежнюю проверку личности узла.
- `src/ryadom/signaling.rs`: новый путь требует локальную настройку TURN и
  использует существующий Relay-only ICE. Прямой или неизвестный маршрут
  отклоняется; обычный поиск P2P с резервным TURN остаётся прежним.

Два регрессионных теста проверяют отсутствие настройки TURN и запрет прямого
или неизвестного маршрута в принудительном режиме. Их включает штатная команда
Windows-сборки `cargo test --locked --lib --features flutter,ryadom ryadom`.
Общие WebRTC-компоненты, браузер, служба и разрешения доступа не менялись.
Native suite нового семейного ядра: 21 тест прошёл, 2 внешних испытания пропущены.
На двух Windows-ПК проверены разрешение владельца и изображение через TURN
только помогающего ПК; принимающее ядро не имело настроенного TURN.
Ввод, звук, файлы, восстановление связи и длительная работа не проверялись.
