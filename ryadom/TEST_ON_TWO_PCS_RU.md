# Проверка «Рядом» на двух ПК

Это сборка разработки для испытаний Windows 10/11 x64. Полный выпуск ещё
не прошёл приёмку; протокол находится в `acceptance.json`.
Новая сборка от 15.11 использует службу поиска на alwaysdata Free. Владелец
подтвердил повторную проверку WebSocket без VPN в сети второго ноутбука.
Полный удалённый сеанс этой сборки ещё нужно проверить по шагам ниже.
При передаче программы передайте также архив `Ryadom-Sources-development.zip`
с соответствующими исходниками и лицензией AGPL-3.0.

**Что передавать на второй ноутбук:** `Ryadom.exe` — для разовой помощи без
установки; `Ryadom-Setup.exe` — для установки службы и постоянного доступа.
Оба содержат одно и то же ядро и встроенную семейную настройку ExpressTURN.
Portable работает без прав администратора с обычными окнами; экран входа и
защищённые окна UAC требуют установленной службы либо отдельного повышения.
Для постоянного доступа после установки задайте пароль. Обновите обе стороны.

При переходе с portable запустите новый Setup из той же учётной записи Windows:
ID, уже заданный постоянный пароль и настройки переносятся автоматически.
Предварительно удалять portable и вводить пароль заново не требуется. Если
программа уже установлена, запуск portable открывает установленную версию.

В установщике есть галочка **«Запускать вместе с Windows»**, включённая на новом
ПК. После установки её можно изменить в **Настройки → Общие → Автозапуск**.
Она управляет службой и значком в трее; Windows может запросить права администратора.
Изменение не прерывает текущий сеанс. При выключении после перезагрузки нужно
самостоятельно открыть программу. Проверьте оба положения и сохранение выбора
при обновлении; перезагрузку выполняйте только когда готовы закончить текущий сеанс.

Установщик 15.11 проверен на этом ПК: установка/обновление с UAC, служба Auto
от LocalSystem и повторный запуск прошли. Удалённое управление UAC и работа
после перезагрузки остаются проверкой на двух ПК. Ошибка 9059 исправлена.

1. Запустите новый `Ryadom.exe` либо установите `Ryadom-Setup.exe` с подтверждением
   Windows. Для первого опыта установка не нужна. Используйте разные сети, например домашний Wi-Fi и мобильную
   точку доступа на втором ПК.
2. На удалённом компьютере дождитесь ID в карточке «Дать доступ». Нажмите
   «Скопировать ID» или продиктуйте девять цифр по три. Номер показывается
   после регистрации в службе поиска и может смениться при конфликте.
3. На управляющем ПК вставьте ID в «Подключиться». На удалённом ПК подтвердите
   ожидаемый запрос кнопкой «Разрешить». До разрешения управление не выдаётся.
4. Проверьте изображение, мышь и ввод в пустом тестовом документе. На панели
   сеанса найдите P2P или TURN. Наведение объясняет, расходуется ли квота TURN.
5. Завершите сеанс. Для последующих подключений можно задать отдельный постоянный
   пароль на удалённом ПК и выбрать его сохранение только на своём устройстве.

`Ryadom.exe` — один переносной файл. При запуске он распаковывает рабочие файлы
в `%LOCALAPPDATA%\ryadom`; настройки и личность сохраняются в профиле Ryadom.
Программа должна оставаться запущенной для приёма подключения.

`Ryadom-Setup.exe` — вариант того же пакета с запуском установки. Установка службы
требует подтверждения администратора Windows. После неё отдельно проверяются
блокировка, экран входа, UAC и повторное подключение после перезагрузки.
Работа этих сценариев на двух ПК пока не подтверждена.

Для обновления сначала завершите сеанс и закройте «Рядом» на обоих ПК,
затем замените переносной EXE или запустите новый установщик.
Обычный portable не требует прав администратора для первого подключения.
Команда «Повысить права на удалённом ПК…» используется отдельно, когда нужна
работа с административными окнами. Без известных данных администратора Windows
повышение для стандартного пользователя невозможно.

Проверьте новые функции:

- Откройте «Историю подключений» и повторно подключитесь к сохранённому ноутбуку.
- Без постоянного пароля должно сразу ожидаться разрешение владельца.
- Подвигайте мышь физически за удалённым ПК: управляющий видит оранжевый курсор.
- Остановите мышь на 5 секунд: оранжевый курсор должен исчезнуть у управляющего;
  масштабирование не должно показать его снова. Новое движение возвращает курсор.
- Включите просмотр с указкой: её с именем управляющего видит только человек
  за удалённым ПК. Вернитесь к управлению и переподключитесь: указка не остаётся
  на передаваемом экране. Переключайте мониторы, в том числе отдельными окнами:
  право управления и работа щелчков должны сохраняться.
- Примите разовый доступ, отключите сеть дольше 10 секунд и восстановите её
  до истечения 5 минут: должно появиться восстановление с отсчётом, затем тот же
  сеанс без нового запроса. Проверьте сохранение монитора, масштаба и режима
  просмотра, отпускание клавиш, отсутствие повторов команд терминала.
- Отдельно оставьте сеть выключенной более 5 минут: автоматические попытки должны
  закончиться. Повторите обрыв и нажмите «Завершить доступ» на удалённом ПК:
  прежний клиент не должен восстановить доступ. Ручное «Отключиться» тоже
  завершает разрешение. Проверьте постоянный пароль отдельно после перезапуска
  принимающего процесса.
- В окне принятого входящего сеанса видна кнопка «Поменяться сторонами»; окно
  не должно само сворачиваться. Нажатие вызывает подтверждение на другом ПК,
  до согласия рабочий стол другой стороны не открывается.
- Включите «Просмотр с указкой»: на удалённом ПК видна ваша оранжевая указка,
  щелчок только отмечает место, не нажимая элементы Windows.
- Выберите кодек «Авто — проверка кодеков». Прокручивайте тестовый документ
  примерно 30 секунд; затем откройте значок скорости и сравните FPS, мс и КБ/с.
  При неподвижном экране программа должна честно сообщить о нехватке данных.
  Проверьте ручной VP8: автоматическая проверка не должна его переключать.
- Подсказки верхней панели должны появляться сразу. Команда печати текста
  из буфера выполняется один раз; обычная синхронизация буфера управляется отдельно.
- После первого успешного подключения в истории должны появиться цифры ID,
  а имя ПК — ниже. Несколько записей располагаются компактной сеткой; нажатие
  повторно подключает к сохранённому устройству. У старых записей цифры заполнятся
  после следующего подключения к новой версии. Проверьте читаемость при своём DPI.

Оба приложения принимают подключения и подключаются к другим ПК. Вручную
открывать порты на роутере для первоначального опыта не требуется. Согласование
использует нашу службу на alwaysdata; данные сеанса идут по WebRTC напрямую или через
TURN одного или обоих участников. Проверка личности и разрешение владельца сохраняются в обоих
случаях. Совместимость с обычными клиентами RustDesk не предусмотрена.

В семейной Windows-сборке ExpressTURN уже встроен. Вводить адрес и пароль
на другом ПК не требуется. Программа сначала пробует прямой канал и может
выбрать резервный TURN. Общий пароль скрыт внутри EXE, но его можно извлечь:
передавайте эту сборку только согласованному кругу родственников.
Собственный TURN можно задать значком сети на главном экране. После изменения
перезапустите приложение. В веб-сборке общего пароля нет; там доступна личная
настройка WebCrypto/IndexedDB или relay-кандидат удалённого приложения.

На Free ExpressTURN указаны 1 000 ГБ/месяц; бесплатный узел использует порт 3478.
Корпоративная сеть может блокировать этот порт. Большие файлы и видео через TURN
расходуют общую квоту. Прямое P2P-подключение не расходует TURN-квоту. Если квота закончилась,
сеанс в сети, требующей ретрансляции, не установится.

Если соединение не получилось, сохраните точный текст ошибки, тип сети на обоих
ПК и показанный тип канала. Не присылайте постоянные пароли и файлы конфигурации
с ключами. Для успешного опыта запишите версии Windows, P2P/TURN, разрешение
экрана и какие действия реально проверены.

## Помощник P2P и длительная аренда

1. Обновите оба ПК и нажмите «Помочь прямому подключению». Проверьте сохранение
   включения после перезапуска, UAC только для правила UDP и продолжение остальных
   проверок после отказа UAC. Сравните portable и установленную службу.
2. Запишите PCP/NAT-PMP/UPnP, назначенный порт и фактический срок аренды.
   Само сообщение «порт настроен» не должно обещать P2P.
3. Проверьте LAN, разные сети IPv4/STUN и глобальный IPv6. При запрете прямого
   пути сначала выполняется поиск до 8 секунд, затем TURN; общий предел установки
   канала 45 секунд. На панели указан фактический P2P IPv4/IPv6 или TURN.
4. При TURN включите помощник на втором ПК. Через 15/45 секунд или по «Проверить
   P2P» должен появиться проверенный путь. «Перейти на P2P» не требует нового
   подтверждения. Неудачная проверка не закрывает работающий TURN.
5. Держите настоящий P2P-сеанс **дольше часа**, в том числе с окном в трее.
   Зафиксируйте несколько продлений на роутере без замены порта и плановых
   разрывов. Повторите с меньшей арендой и временным отказом продления.
6. Выключите помощник во время P2P: очистка должна отложиться до завершения
   использующего правило канала. После завершения удаляется только собственный
   проброс; после аварийного выхода он должен истечь. Чужие правила сохраняются.
7. Оборвите большие передачи файлов; после восстановления сравните SHA256
   отправленного и полученного файлов. Прерывайте запись: должны получиться
   воспроизводимые отдельные WebM-фрагменты. В браузере при начале записи
   выбирается папка для этих фрагментов.
## Проверка TURN только на стороне помощника

Отдельный пакет для принимающего ноутбука: `dist/one-sided-turn-test`.
Он собирается без `ryadom-bundled-turn`; собственные параметры TURN туда не
включаются. На помогающем ПК используется его текущая настроенная версия.

1. На принимающем ноутбуке с установленной службой обновить приложение через
   `Ryadom-Setup.exe` из этого пакета. Если использовался только Portable,
   полностью закрыть старую копию и запустить новый `Ryadom.exe`.
2. Дождаться ID, сообщить его помощнику и разрешить обычное подключение. TURN,
   профили, адреса серверов и сетевые пароли на ноутбуке вводить не нужно.
3. На помогающем ПК подключиться к этому ID. Если выбран TURN, дополнительно
   подтвердить отсутствие TURN у фактически принимающего ядра. Один значок TURN
   без этой проверки не определяет, чья allocation использована.

Для установленной версии read-only проверка в PowerShell:

```powershell
& "$env:ProgramFiles\Ryadom\Ryadom.exe" --ryadom-network-status | Out-String
```

На принимающем ноутбуке ожидаются `acceptingBackend: true`, `accepting: true`,
`bundledTurn: false`, `turnServerCount: 0`, `configured: false`. `processId`
принадлежит отвечающему ядру. Отсутствие или старая версия IPC-ответа вызывает
ошибку вместо подстановки настроек окна. Команда не меняет сеть, службу и TURN.
Счётчик отражает эффективные параметры на момент запроса. Если прежняя личная
настройка не читается или не расшифровывается, она не входит в этот счётчик.
Готовность службы поиска подтверждается отдельно: появившимся ID и подключением.

Старый установленный backend может обслуживать новый Portable. Поэтому при
наличии службы нужна именно её обновлённая сборка; запуск другого окна сам по
себе не доказывает отсутствие встроенных данных в принимающей службе.

P2P означает успешный прямой путь, но не проверку резервного TURN. Если он
побеждает, отдельный тестовый клиент может принудительно выбрать relay только
для своего соединения. Брандмауэр и системный UDP для этого не отключаются.

Локальная проверка двух Edge RTC peers уже подтвердила `relay ↔ srflx` при
настройке TURN только у помощника: 65 536 байт в каждую сторону, все байты
совпали. Это один физический ПК, не приёмка между двумя сетями. Реальная
проверка с ноутбуком остаётся ожидающей владельца.
