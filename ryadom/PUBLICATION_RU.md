# Публичный репозиторий «Рядом»

Официальный fork: https://github.com/chico1969/ryadom . История RustDesk
сохраняется. Рабочую ветку нужно строить от закреплённого коммита 1.5.3, а не
подмешивать актуальные изменения upstream master без проверки.

## Что содержится в чистой поставке исходников

| Путь | Назначение |
| --- | --- |
| `src/ryadom` | Связь, сопряжение, восстановление и команды приложения |
| `flutter/lib/ryadom` | Собственный Windows-интерфейс |
| `flutter/web/js` | Открытый браузерный движок |
| `ryadom` | Сборка, патчи подмодуля, сервер согласования и инструкции |
| `libs`, остальной `src`, `flutter` | Используемое ядро и зависимости RustDesk |
| `.github` | Сборка, подпись и участие в проекте |

Локальные SDK, кэши, журналы, данные устройств, `.tools`, `target`, `dist`,
`node_modules` и результаты Flutter-сборки не публикуются в Git. Требуемые
generated bridge sources включаются в архив соответствующих исходников;
GitHub создаёт bridge из исходников штатным workflow.

Не удаляем исходники других платформ или старого интерфейса только из-за того,
что первая цель — Windows: общее ядро и Cargo workspace всё ещё используют
условные модули и ссылки на эти каталоги. Удаление без отдельной проверки
усложняет сборку и дальнейшее получение исправлений безопасности upstream.
Ненужные автоматические upstream CI-запуски можно ограничить отдельным guard,
не переписывая их реализации.

## Оформление и обнаружение на GitHub

Главная страница содержит назначение, запуск, состояние разработки, сеть и
ссылки на участие/безопасность. About и релевантные Topics уже настроены.
Следующие материалы: проверяемый development release, короткое видео настоящего
подключения и реальные отчёты испытателей. Не добавляем выдуманные отзывы,
пользователей, показатели производительности, бейджи пройденных проверок или
обещание бесплатного неограниченного TURN.

До набора испытателей нужно включить Issues и, если доступно, private
vulnerability reporting. При публикации release указывать статус pre-release,
версию, изменения, известные ограничения, подпись и соответствующие исходники.
Семейный EXE с общими ExpressTURN-данными на публичный release не загружать.
