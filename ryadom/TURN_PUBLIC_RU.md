# TURN для публичного «Рядом»

Решение по состоянию на 15.11.2026. Это архитектура и условия выбора, не уже
развёрнутый общедоступный резерв. Семейные сборки и текущий ExpressTURN не меняются.

## Настройка своего TURN: предлагаемое поведение

Это предложение к реализации; импорт/экспорт сетевых профилей пока не добавлен
в приложение. Текущая личная настройка TURN и семейная сборка остаются рабочими
отдельными механизмами.

| Вариант | Удобство | Подпись и распространение |
| --- | --- | --- |
| Один Setup + сетевой профиль | Владелец вводит TURN один раз, родственники импортируют профиль | Официальный EXE остаётся неизменным и сохраняет подпись; профиль передаётся отдельно |
| Собственная семейная сборка | Родственник запускает уже настроенный EXE | Нужны инструменты сборки; новый EXE нужно подписывать отдельно; внутри остаются извлекаемые TURN-данные |
| Профиль с серверной выдачей | После разрешённого сопряжения данные приходят автоматически | Основной ключ хранится на сервере; нужны контроль доступа, квоты и обслуживание |

Рекомендованный первый этап: один подписанный Setup, настройка в программе и
отдельный переносимый профиль. Дополнительно документировать сборку со своим
профилем для владельцев, которым она действительно нужна. Это сохраняет простой
путь для родственников и не требует выдавать им инструменты разработчика.

Предлагаемый мастер **«Сеть → Мой TURN»**:

1. Владелец выбирает статические данные своего провайдера либо сервер временной
   выдачи. Для первого варианта вводит адреса, логин и пароль; API-ключ управления
   аккаунтом в приложение не вводится.
2. Программа проверяет формат, защищённое соединение где применимо, успешную
   TURN allocation и доступность нужных транспортов. Реальный сеанс проверяется
   отдельно со вторым ПК: успешный тест сервера ещё не доказывает соединение.
3. Настройка сохраняется локально с защитой Windows. У установленной службы
   должна быть собственная защищённая копия с ограниченным доступом; нельзя
   просто копировать user-DPAPI blob в профиль LocalSystem. Изменение машинной
   настройки требует соответствующих прав; Portable хранит пользовательскую.
4. Владелец выбирает «Экспортировать сетевой профиль». Экспорт со статическим
   паролем предлагается защитить отдельной парольной фразой. Получатель вводит
   её один раз при импорте. Файл показывается как содержащий сетевые секреты;
   его не публикуют в Issues, Git или общих Releases.
5. Импорт показывает имя профиля, службу поиска и TURN-адреса, требует явного
   применения, проверяет версию и допустимые поля. Профиль содержит только
   сетевые настройки, не ID/ключи устройства, пароли доступа к ПК, доверие или
   команды запуска. Приложение не исполняет скрипты из профиля.

Шифрование экспортного файла защищает пересылку и хранение, но получатель,
которому разрешено использовать статический пароль, технически может извлечь
его из своего приложения. Основной ключ провайдера не включается даже в
собственную сборку. Сетевой пароль не даёт доступ к рабочему столу.

Для собственной сборки использовать отдельный локальный конфиг вне Git и
явный private build-режим. Результаты складывать отдельно от публичных файлов;
сборщик не должен изменять уже подписанные EXE или обещать сохранение их подписи.
Готовить один ZIP с официальным Setup и отдельным профилем допустимо, но
автоматически применять найденный рядом конфиг без проверки и подтверждения
не следует.

Формат профиля сразу версионировать с двумя способами TURN: `static` и
`credential-service`. Второй можно добавить позже с сохранением пользовательского
сценария. Выдачу временных данных разрешать после проверки профиля/приглашения и
ключа устройства; открытый endpoint для всех не обеспечивает защиту квоты.

## Практический выбор

Для первой публичной разработки: P2P первым и настройка собственного TURN
владельцем. Родственникам можно передавать его отдельную семейную сборку или
конфигурацию. Публичные исходники и CI не содержат общего семейного пароля.

Общий резерв для всех пользователей требует серверной выдачи временных данных,
контроля доступа и ограничений расхода. Не включать его до подтверждения бюджета,
доступности из целевых сетей и способа жёстко остановить расход без списаний.
Бесплатное ПО не означает бесплатный неограниченный ретранслируемый трафик.

## Проверенные варианты

| Вариант | Что подходит | Ограничение для нас |
| --- | --- | --- |
| ExpressTURN Free | Уже работает у семьи; провайдер заявляет 1000 GB/месяц | Shared-secret authentication для временных учётных данных доступна у Premium; общий статический пароль нельзя выпускать для всех |
| Cloudflare TURN | Документированная серверная выдача временных данных; 1000 GB/месяц общей SFU/TURN квоты | Далее $0.05/GB; это не подтверждённый тариф без списаний. TURN и API ещё надо проверить без VPN в нужных сетях |
| Metered Open Relay | Заявляет 20 GB/месяц и API | Это общая ограниченная квота; реальные требования аккаунта/карты проверяются в кабинете. Наши предыдущие ограничения регистрации/доступа не считаем устранёнными |
| Собственный coturn | Открытый сервер и временные HMAC-учётные данные; полный контроль | Нужны доступный сервер, публичный адрес/порты и оплачиваемый кем-то трафик. Обычный бесплатный веб-хостинг не становится TURN-сервером |

Источники провайдеров:

- ExpressTURN Free и механизм shared-secret: https://www.expressturn.com/
- Cloudflare credentials: https://developers.cloudflare.com/realtime/turn/generate-credentials/
- Cloudflare pricing: https://developers.cloudflare.com/realtime/sfu/platform/pricing/
- Metered: https://www.metered.ca/tools/openrelay/
- coturn REST credentials: https://github.com/coturn/coturn/wiki/turnserver#turn-rest-api

На публичных страницах Cloudflare, проверенных в эту дату, не найдено обещания
жёсткого отключения без оплаты сверх квоты или универсальной доступности без
карты. Не активировать такой тариф только из-за числа «1000 GB».

## Предлагаемая серверная выдача

1. Клиент использует P2P и запрашивает резерв только когда он необходим.
2. Сервер проверяет разрешённый профиль/приглашение и доказательство владения
   ключом устройства через случайный одноразовый challenge. ID не авторизует
   расход. Открытая регистрация любых ключей сама по себе не защищает от злоупотреблений.
3. Только сервер хранит provider API token или HMAC secret. Клиент получает
   короткоживущие `urls`, `username`, `credential`, `expiresAt`.
4. Сервер ограничивает выдачу на устройство/профиль/IP, число активных подключений,
   общий бюджет, повторы и автоматические запросы. Не доверяет числу переданных
   байтов, присланному модифицируемым клиентом.
5. Расход учитывается на стороне провайдера/собственного TURN. Нужны реальная
   статистика, предельная квота и способ прекратить новые allocations/отозвать
   доступ. Счётчик в интерфейсе полезен, но не является финансовой защитой.
6. До истечения временных данных клиент обновляет их для новых allocations,
   ICE restart и восстановления. Срок данных не должен вводить плановые обрывы
   сеанса. Это проверяется с выбранным провайдером, а не предполагается по таймеру.

Временные данные всё равно можно извлечь из клиентского процесса и использовать
до истечения срока. Полностью запретить их применение другим ПО невозможно;
задача архитектуры — ограничить ущерб и не раскрывать основной ключ.

Для варианта без аккаунтов приложения можно оставить семейные приглашения и
список разрешённых устройств у владельца. Публичный безусловный endpoint выдачи
TURN-паролей не подходит: его сможет вызывать любой, независимо от CORS и наличия
официального EXE.

## Проверки перед включением общего резерва

Проверить настоящий TURN allocation и сеанс из двух сетей без VPN, отзыв и
истечение данных, недоступность API, исчерпание квоты, поддельный challenge,
модифицированный клиент и отсутствие планового обрыва при обновлении. Отдельно
подтвердить у провайдера применимые условия распространения и защиты расходов.
