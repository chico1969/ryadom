# Рядом

Открытый проект удалённой помощи для Windows 10/11 x64 на основе RustDesk 1.5.3.

## Состояние

Идёт разработка. Этот репозиторий пока не является проверенным готовым выпуском.
Результаты сборки и реальных испытаний фиксируются отдельно. 15.11.2026 на ПК
разработки проверены установка и обновление с повышением UAC, автозапуск службы
LocalSystem, её остановка/запуск и подписанный WebRTC-канал до авторизации.
Удалённый защищённый рабочий стол UAC, перезагрузка и матрица двух ПК ещё требуют
приёмочных испытаний.

## Соединение и бесплатная инфраструктура

Для родственников не требуется регистрация или собственный API-ключ.
С 14.11.2026 согласование выполняется собственной небольшой службой на
alwaysdata Free. Адрес закреплён в `signaling.json` и одинаков в Windows
и браузере. Эта служба
передаёт только служебные сообщения. Пароль, экран, звук, файлы и команды должны
передаваться только через авторизованный зашифрованный WebRTC-канал.

Причина изменения — `HTTP 403 Forbidden` от `0.peerjs.com` и недоступность
адресов Workers/Pages без VPN в сети второго ноутбука. Служба перенесена на
`ryadom-family.alwaysdata.net`; HTTPS и серверный протокол проверены.
Владелец подтвердил успешную повторную проверку WebSocket без VPN на втором
ноутбуке. Это проверка службы поиска; полный сеанс текущей сборки на втором ПК
и перезагрузка остаются отдельными испытаниями.

При отказе регистрации окно теперь показывает «ID недоступен» и объяснение,
включая HTTP 403. Фиктивный номер не выдаётся; повторные попытки идут с паузами
до 60 секунд. Копирование недействующего ID отключено. Для новой службы нужно
обновить обе стороны: старые сборки продолжают обращаться к PeerJS или Cloudflare.

На alwaysdata выбран Free: 1 ГБ диска, 256 МБ RAM, 0.25 CPU. Карта и платный
тариф не подключались; действуют ресурсные ограничения площадки. Сервер ограничен
128 одновременными служебными WebSocket-соединениями для семейных испытаний.
Ключ SSH для развёртывания хранится только на ПК владельца и в клиентские
сборки не входит. Исходник сервиса — `signaling-service/peer-server`;
аккаунт хостинга нужен только владельцу.

Доступ разрешается подтверждением владельца или отдельным паролем удалённого ПК.
В Windows-код добавлена защита сохранённого пароля DPAPI. Публичный ID служит
адресом, но не разрешением доступа.

По согласованному изменению от 13.11.2026 добавлен резервный TURN. ICE отдаёт
предпочтение прямым маршрутам; при выбранной relay-паре трафик идёт через TURN.
Сеанс сохраняет проверку личности, DTLS и пароль/подтверждение владельца.
В окне сеанса есть индикатор P2P/TURN по фактически выбранной паре кандидатов.
Прежние HBBS/HBBR-маршруты RustDesk не включаются.

Семейная тестовая Windows-сборка `-BundleTestTurn` автоматически использует
ExpressTURN: на другом ПК адрес и пароль вводить не нужно. Общая конфигурация
зашифрована вместе с ключом внутри EXE. Это обфускация: получатель EXE может
восстановить пароль и расходовать общую квоту. Такой режим выбран владельцем
для себя и родственников. Пароль не входит в git, архив исходников или веб-сборку.
Программа не вводит проверок лицензии и платных функций; лицензия AGPL-3.0
исходного проекта и условия внешних служб сохраняются.

Обычная сборка без этого флага не содержит общих данных. Личный TURN можно
задать в Windows с защитой DPAPI текущего пользователя; в браузере — через
WebCrypto/IndexedDB. После изменения Windows-настроек перезапустите приложение.
Секретный API-ключ управления аккаунтом не используется. Защищённая выдача
временных TURN-данных через сервер пока не реализована.

На главном экране показывается короткий ID из девяти цифр, сгруппированных по три.
Он регистрируется отдельным именем в текущей службе поиска. Сервер отклоняет
занятое имя; тогда приложение выбирает другое. ID показывается после регистрации,
а при потере регистрации очищается. Это уникальность активной регистрации,
а не пожизненное закрепление номера. Сохранённые компьютеры и пароли привязаны
к отдельной криптографической личности, а не к короткому номеру.

Один участник может использовать свой TURN, а другой — подключиться к его
relay-кандидату без получения TURN-пароля. В сетях, где у второго участника
заблокирован UDP, может потребоваться TURN и с его стороны. Это проверяется
на физических ПК. Обычная сборка без личной настройки сама не создаёт TURN-выделение,
но может использовать разрешённую relay-пару другого участника.

`turn.example.json` показывает формат данных для локальных испытаний. Личный
`.tools/turn.local.json` исключён из git и архива исходников и не читается
приложением; его используют только явные локальные тесты. `prepare-network.ps1`
не передаёт данные компилятору.

Для семейной сборки выбран ExpressTURN; на странице Free указаны 1 000 ГБ/месяц
и TCP/UDP 3478. Порты 80/443 и TLS не входят в проверенный бесплатный вариант.
Прямые подключения квоту TURN не расходуют. Cloudflare Realtime в этом аккаунте
потребовал платёжный способ и согласие на списания после квоты: не активирован.
По [FAQ ExpressTURN](https://www.expressturn.com/) график расхода в кабинете
доступен платным аккаунтам; точный остаток бесплатной квоты приложение не получает.

Публичная служба согласования не имеет гарантии доступности. Если сети не дают
установить канал, программа должна сообщить об этом, не переходя на платные услуги.

## Исходная основа

Точные версии закреплены в `upstream.lock.json` и `toolchain.lock.json`.
Оригинальная лицензия находится в корневом `LICENCE`; уведомления авторов сохраняются.

## Что проверено

### Автозапуск Windows — 15.11.2026

В Setup добавлена галочка «Запускать вместе с Windows». При первой установке
она включена; повторная установка загружает ранее сохранённый выбор. В приложении
тот же параметр доступен в «Настройки → Общие → Автозапуск».

Включение настраивает автоматический запуск службы и значок в трее при входе
Windows. Выключение переводит службу в ручной запуск и убирает ярлык из общей
автозагрузки. Текущая работа службы и подключения при смене параметра продолжаются;
параметр определяет следующий запуск Windows. После перезагрузки при выключенном
автозапуске программу необходимо запускать самостоятельно.

Изменение системной настройки может требовать UAC. До успешного применения выбор
не считается сохранённым; при отмене приложение показывает ошибку и перечитывает
состояние Windows. Параметр хранится отдельно от ID, пароля и настроек сеанса,
поэтому обновление Setup сохраняет его.

Для установки из командной строки поддержаны `--silent-install --autostart`
и `--silent-install --no-autostart`. Без дополнительного флага обновление использует
сохранённый выбор, а на новом ПК — включённый автозапуск. Текущий статус фактической
проверки Windows записан в `verification.json`; наличие сборки не означает проверку
реальной перезагрузки.

На этом ПК проверены оба положения через локальный API: служба не меняла PID
и оставалась запущенной. Реальный Setup последовательно прошёл выключенную
галочку, обновление с сохранением выключенного выбора и включённую галочку.
Все 91 файл установленного приложения совпали со сборкой; ID, хранилище пароля,
соль и настройки приёма сохранились. Исходный автозапуск включён обратно.
Перезагрузка и удалённый UAC в этой проверке не выполнялись.

### Установщик, история и читаемость — 15.11.2026

При первой установке Setup переносит личность устройства, сохранённый короткий
ID, постоянный пароль с солью и настройки приёма из portable в профиль службы.
Перенос выполняется до создания новой личности службы и не зависит от дат файлов.
Промежуточный снимок защищён механизмом установщика; ключ устройства остаётся
под DPAPI, личная настройка TURN перепаковывается для службы на этом же ПК.
История и настройки интерфейса остаются в прежнем профиле пользователя Windows.
Запускайте Setup из той же учётной записи, в которой использовали portable.
Обновление уже установленной версии сохраняет конфигурацию существующей службы.

Если программа уже установлена, обычный запуск portable открывает установленный
EXE. Это сохраняет проверку пути исполняемого файла при локальном IPC; ошибка
`reset by the peer` больше не маскируется бесконечным получением ID из чужого
процесса. Панель P2P объясняет потерю локальной связи и автоматически убирает
ошибку после успешной проверки.

На этом физическом ПК перенос проверен со случайной тестовой личностью:
portable и установленная служба приняли один и тот же пароль по настоящему
прямому WebRTC; оба ID, хеш пароля/соль и настройки совпали. После проверки
восстановлена исходная конфигурация. Отдельное обновление установленной версии
сохранило прежние ID, пароль и настройки; служба снова запущена.

Исправлена ошибка установки 9059: внутренний EXE теперь называется `Ryadom.exe`,
как ожидают служба и ярлыки. Проверены первая установка и обновление текущим
пакетом, совпадение EXE, Rust DLL и Flutter AOT с собранными файлами, Running/Auto
и LocalSystem, смена PID после перезапуска. UAC и защищённый запрос Windows включены;
проверочный процесс действительно получил административные права. Это не проверка
управления удалённым окном UAC и не испытание перезагрузки.

История показывает девять цифр ID крупным основным текстом, имя ПК — ниже.
Компактная сетка автоматически выбирает до четырёх колонок. Старые записи,
в которых числовой ID ещё не сохранялся, дополняются после следующего успешного
подключения к новой версии. Номер может измениться, поэтому повторное подключение
проверяет сохранённую криптографическую личность устройства.

Текст Windows-интерфейса использует Segoe UI, более плотное начертание,
основной размер 15–16 и подписи 13–14 логических пикселей. Вторичный текст стал
темнее; компактная компоновка проверена при масштабе текста 125% и 150%.
Веб-интерфейс получил соответствующие размеры и контраст.

### Обновление управления и автовыбора кодеков

В новом пакете portable начинает обычный сеанс без автоматического запроса
администратора. Повышение запрашивается отдельно; уже повышенный процесс или
установленная служба скрывают повторный запрос. Если пользователь Windows
не администратор, для повышения всё равно нужны данные администратора.
Правила UAC и защищённый рабочий стол не обходятся.
Поведение стандартной учётной записи описано в
[документации Microsoft по UAC](https://learn.microsoft.com/windows/security/identity-protection/user-account-control/how-user-account-control-works).

Удалённый курсор показывается оранжевым по умолчанию. Режим «Просмотр с указкой»
отправляет только положение указки и визуальную отметку щелчка; он не нажимает
кнопки и не вводит текст на удалённом компьютере. Лишние переключатели курсора
убраны. Подсказки панели появляются без задержки; источники ввода и режимы
клавиатуры получили пояснения. «Напечатать текст из моего буфера…» — разовое
действие: отправка текста как ввода, а не переключатель синхронизации буфера.

Оранжевый курсор человека за удалённым ПК скрывается через 5 секунд без движения
и появляется при новом движении. Изменение масштаба не продлевает его показ.
Указка с именем управляющего видна только человеку за удалённым ПК: на Windows
10 2004 и новее её окно исключается из захвата и очищается при смене режима
или завершении сеанса. На более ранних Windows эта указка не запускается.
Задержанные координаты курсора не блокируют мышь управляющего. Мониторы одного
подтверждённого сеанса используют общее право управления.

При сетевом обрыве новая версия восстанавливает разрешённый сеанс до 5 минут
без повторного подтверждения. Секрет восстановления хранится только в памяти;
«Отключиться» и «Завершить доступ» его отзывают. Перезапуск принимающего процесса
очищает разрешение; постоянный пароль работает отдельно.
Кнопка «Поменяться сторонами» доступна в окне принятого
входящего сеанса; другая сторона подтверждает показ своего рабочего стола.
Это окно больше не сворачивается автоматически через три секунды.

При отсутствии постоянного пароля клиент сразу ожидает подтверждения владельца.
История на главной странице загружает штатные сохранённые подключения и
повторно подключается по криптографической личности устройства, не по временному ID.

«Авто — проверка кодеков» выполняет короткие пробы доступных кодеков в текущем
сеансе. Во время проверки прокрутите документ или перемещайте окно. При одном
качестве изображения и разрешении сравниваются фактические FPS, задержка и
трафик. Выбор отдаёт приоритет плавности и задержке, при близких результатах —
экономичности. Режим полного цвета 4:4:4 Windows сохраняется. Это не объективное
сравнение качества по эталонному изображению: одинаковый параметр качества
разных кодеков не гарантирует одинаковую визуальную точность.
При неподвижном экране победитель не выдумывается: сохраняется прежний кодек.
На панели есть результаты и повторная проверка. Ручной выбор отменяет пробы.
Если ранее уже был выбран VP8 вручную, один раз выберите «Авто» для включения
проверки. Смена качества/разрешения прерывает сравнение; его можно повторить.

Новые курсоры, UAC и автовыбор требуют проверки на двух физических ПК с новой
версией на обеих сторонах. Автоматические тесты и сборка не заменяют эту проверку.

Собран отдельный Flutter веб-интерфейс и собственный TypeScript-движок. В Edge
проверены публичное согласование без личного API-ключа, прямой локальный канал,
парольный обмен с тестовым узлом протокола, отказ при подмене DTLS-отпечатка,
декодирование кадра, чат и воспроизведение записанного WebM. Пароль успешно
сохраняется и удаляется через WebCrypto/IndexedDB.

Дополнительно на этом ПК проверен настоящий Windows-хост из переносного EXE:
подтверждение владельца, подписанная личность и DTLS, авторизация с правом
управления и получение кадра 1920×1080. Пара кандидатов host↔host без relay.
Проверен и настоящий внешний TURN: два браузерных узла передали 64 КБ
искусственных данных по паре relay↔relay с полным совпадением байтов.
С ExpressTURN проверен настоящий Windows-хост: подпись устройства и DTLS
до разрешения рабочего стола, выбранная relay-пара и выдача relay-кандидата
самим хостом. Публичный поиск по девяти цифрам вернул подписанную личность;
попытка занять активный номер отклонена, исходная регистрация сохранилась.
Эти ранние проверки не заменяют два физических ПК в разных сетях и полный набор функций.
Тест записи использует приёмник файла в памяти, без проверки реального диалога
сохранения и большого файла. Полная готовность проверяется отдельно.

Microsoft C++ Build Tools 2022 установлены; LLVM 15.0.6 и Python 3.12.10
подготовлены локально. Нативные библиотеки собраны; `cargo check` и девять
тестов ядра прошли. Windows Flutter/C++-компоненты скомпилированы.
Rust DLL и первые переносные EXE собраны. Обновлённая сборка включает компактный
главный экран, получение ID и резервный TURN; установка службы требует испытания.
Для Flutter-плагинов на этом ПК созданы локальные NTFS junctions;
Developer Mode Windows не переключался. `Ryadom.exe` и `Ryadom-Setup.exe`
находятся в `dist/development`; это пакеты разработки для испытаний.

DPAPI-путь Windows прошёл отдельный тест сохранения/открытия пароля:
сохранённые парольные хеши привязаны к пользователю Windows, ключ устройства —
к компьютеру для использования установленной службой. ID вычисляется из ключа,
а подпись связывает его с DTLS-каналом; пароль и разрешение проверяются отдельно.

## До готового выпуска

- Проверить установку, удаление и работу службы из собранного пакета.
- Проверить настоящий EXE ↔ EXE и браузер ↔ EXE между двумя физическими ПК.
- Завершить отдельное сопряжение и отзыв доверенных устройств без включения 2FA.
  Механизм RustDesk сохранён, собственный пользовательский поток не закончен.
- Проверить восстановление Windows- и браузерного сеанса на физических ПК.
  После перезапуска принимающего процесса требуется отдельная авторизация.
- Завершить проверку файлового менеджера, контрольные суммы содержимого и полное
  восстановление передач. В браузере добавлены просмотр папок, создание,
  переименование, удаление с подтверждением, выбор нескольких файлов и
  перетаскивание; интеграция с Windows-хостом не проверена.
  Продолжение загрузки с позиции более
  4 ГиБ отклоняется, чтобы избежать усечения старого 32-битного поля протокола.
- Проверить звук, настоящий терминал Windows, буфер файлов Windows, мониторы/DPI,
  UAC, вход Windows, многопользовательское управление и запись на диск.

## Сборка

Из корня проекта в PowerShell, если инструменты находятся в локальной `.tools`:

```powershell
. .\ryadom\dev-shell.ps1
.\ryadom\build-web.ps1
```

Веб-результат: `ryadom/ui/build/web`. Браузерная проверка:

```powershell
Push-Location flutter/web/js
node scripts/browser-smoke.mjs
Pop-Location
```

Нужен установленный Edge. Используются отдельный временный профиль, тестовые
данные и временные подключения к текущей службе из `signaling.json`. Чужие экраны и файлы
не захватываются; нативный Windows-хост тестом не заменяется.

Для Windows нужны Visual Studio C++ Build Tools с Windows SDK, LLVM 15.0.6,
Python, vcpkg и зависимости `vcpkg.json`. Версии — в `toolchain.lock.json`.

```powershell
.\ryadom\prepare-submodule.ps1
.\ryadom\build-native-deps.ps1
.\ryadom\build-windows.ps1
```

Для семейного тестового EXE подготовьте личный `.tools/turn.express.local.json`
по `turn.example.json`, установите npm-зависимости браузерного движка и выполните
`./ryadom/build-windows.ps1 -BundleTestTurn`. Файл с данными и сгенерированный
`.tools/turn-bundle.generated.rs` не публикуются. Чтобы повторить сборку из
архива исходников, используйте свои TURN-данные либо обычный режим без флага.

FFmpeg не собирается из пути с пробелами. `build-native-deps.ps1` временно
создаёт SUBST-диск к папке проекта и убирает его после окончания сборки.
Исходники остаются в `D:\uni v\ryadom`.

Для `flutter_rust_bridge_codegen` используется закреплённый CI-процесс, а не произвольная локальная версия.
Получены готовые привязки из официального CI: SHA256 и совпадение входного файла
зафиксированы в `ffi-artifact.lock.json`. Архив исходников разработки включает
эти привязки. Для нового git-клона подготовлен workflow `.github/workflows/ryadom.yml`;
его выполнение ещё не проверено.

`hbb_common` остался на закреплённом коммите. Изменения сохраняются в
`patches/hbb_common.patch`; подготовка проверяет повторное применение.

## Результаты и ограничения

Результаты: `build-logs/browser-smoke.json`, `build-logs/npm-audit.json`,
`build-logs/cargo-check.log`, сводка — `verification.json`. Проверка npm после
обновления protobuf не нашла известных уязвимостей runtime-зависимостей;
это не заменяет аудит приложения и испытания Windows-кода.

IP-фильтр прежнего транспорта не применяется к фиктивному адресу WebRTC:
при заданном IP-фильтре подключение отклоняется. Если не удаётся освободить ввод,
передача управления блокируется до перезапуска приложения.

Для публикации подготовлен `hosting/firebase.json`, только для бесплатного Spark.
Платёжный аккаунт и повышение тарифа не настраивались. Публикация не выполнена:
Firebase-проект и авторизация владельца в этой среде отсутствуют.

Изменённые существующие пути: [REGRESSION_SURFACE.md](REGRESSION_SURFACE.md).
